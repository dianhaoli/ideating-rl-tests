## 1. Bottom line

- **One environment is validated with caveats: ShiftHunt.** It is a test of interpretability skill, checked in two model families.
  It is not yet validated as an RL training environment (section 2).
- **Explored, with clear lessons:** FeatureMatch (mostly measures writing style); LatentKnockout (a cheap recipe matches
  the reference; it also produced a research question); BoolIntermediates and LatentDiff (too easy for frontier agents); EditFind, T2Ravel
  and SilentPathway (dropped, each for a stated reason).
- **Small models fail ShiftHunt for capability reasons, not because of the environment** (section 3).
- **ShiftHunt v3 (Oct 4) was stopped at Stage 0 as a negative result** (section 2b). Planted nonlinear modules in otherwise
  linear heads, combined with exact tools, are scriptable through the tool algebra. Real interpretation needs an open
  space of possible cues and heads trained on data.

## 2. ShiftHunt (task/shifthunt; `docs/results/shifthunt/VALIDATION.md`)

**The task.** The agent gets 3-4 linear probes on gemma-2-2b. Each was trained on topic-labelled text in which one listed surface cue may
have been correlated with the label. For each probe the agent must name the cue the probe relies on (or "none"), then give at most 20
Gemma Scope SAE latents whose mean-ablation removes that reliance while keeping the topic reading. The grader reruns the probe on a hidden
balanced test set. Removal is exact arithmetic, and there is no LLM judge. This is the manual step of SHIFT (Marks et al. 2024).
T1 lets the SAE encode any text; T2 encodes only the given samples, so agents must read what latents mean.

**Gates (scripted).** T1: reference 16/16; every recipe, black-box control and attack 0/16. T2: reference v4.2 39/39 on the kept pool;
cheap solvers <= 3/39 = 7.7% (upper CI about 20%).

**Agent runs** (fresh agents, same instances across arms; Wilson 95% CIs):

| arm | pass | named right | null false claims |
|---|---|---|---|
| T1 Opus 5.5 (20) | 19/20 = 95% [76, 99] | 44/44 | 0/26 |
| T1 gpt-6.1-sol (10) | 10/10 [72, 100] | 22/22 | 0/13 |
| **T2 Opus 5.5 (20)** | **15/20 = 75% [53, 89]** | 52/52 | 0/18 |
| **T2 gpt-6.1-sol (10)** | **7/10 = 70% [40, 89]** | 26/26 | 0/9 |
| T1 Haiku 4.5 (10) | 0/10 [0, 28] | 7/22 | 13/13 |
| T1 gpt-6-luna (10) | 0/10 [0, 28] | 19/22 | 5/13 |

- **The difficulty is not specific to Claude.** Both families show the same profile. The OpenAI agents ran through `common/openai_agent.py`
  with no repo or session context. That they match the Claude rates is evidence that the Claude agents' access to the repo did not inflate their scores.
  It is not proof: the direct control would be Opus run fully isolated.
- **T1 is the calibration tier** for frontier models (saturated). **T2 is the candidate tier.** It sits at the top of the mid-band and is bar-sensitive:
  moving tau by +-0.02 gives Opus 14-17/20, and a 10% stricter bar gives sol 3/10 vs Opus 13/20.
- **How large models fail (T2).** Every miss is a removal miss on a correctly named probe, and all of them are on the half of the probes where the reference
  clears the bar by < 0.05. sol's 3 misses: one used only 5 of 20 latents (on the probe both Opus agents also missed); two used a full 20 chosen as
  "cue-pure" or by sample attribution, missing latents that carry the cue through context (-0.003, -0.037). Opus fails the same way.
- **Independent forensics audit** (`docs/forensics/SHIFTHUNT_FORENSICS.md`, written 2026-10-03 by a separate session, verified by its own
  skeptic). The grader is correct: 58/58 regrades are identical. Of Opus's 7 removal misses:
  - 3 are grid noise: margins -0.001 to -0.004, and they pass 23-44% of resamples of the hidden grid;
  - 4 are short lists (9-11 of 20 latents). Padding them to 20 with top-gradient latents, with no interpretation, passes all 4
    (about +3 expected under resampling).
  tau sits at a median 0.80 of the oracle (headroom about 0.06), so the reward is decided near the bar.
  **RL blockers:** the answer is three plain file reads from the sandbox (only the regex audit defends), and the 96-token truncation names
  sign-off/hashtag cues at AUC 0.97-0.98 (ungated). Recipe ceiling given free names: top-|g| latents pass 14/39 kept T2 episodes.
- **Weaknesses** (all in VALIDATION.md):
  - the T2 pool was kept by a reference tuned on it (estimated about 65% on unfiltered instances);
  - outcomes are mostly fixed per instance, so GRPO variance is low;
  - agents are close to interchangeable with the reference pipeline;
  - the regex transcript audit keeps producing new false positives and has known false negatives;
  - Claude test agents are not OS-isolated (section 5);
  - OpenAI ran at effort medium vs Opus at xhigh;
  - n is small.

## 2b. ShiftHunt v3: stopped at Stage 0 (Oct 4, D18; `docs/results/shifthunt3/`)

**Aim** (Dan's brief): make interpretation the bottleneck rather than budget habits or bar placement.

**Design** (`SPEC_v3.md`, with rationale and rejected ideas):
- Each probe adds a planted module over SAE latents of 1-2 text features, combined as single, OR (saturating) or AND (gated).
- No raw logits on the agent's own text, only an ablation-effect tool.
- The claim is structured: verdict + probability, components, combination, latent groups, edit set, numeric predictions.
- Scoring is continuous: calibration 15%, identification 25%, mechanism 25%, edit 35%, plus a per-latent price.
- Two arms: a fixed menu of 16 cues, and an open menu where cues are proven by text pairs checked by exact detectors.

**Gate 0** (`STAGE0.md`; predictions committed before a fresh, unfiltered held-out set; 62 planted slots) passed every gated item:
- top-|g| 5.9%, single-group ablation 0%, v2 recipe 9.8% (all against the < 15% target);
- label-using reference 100% (median removal 0.97);
- the heads really are OR (one variant ≈ both, 0.42 vs 0.44) and AND (each alone ≈ 0, both 0.66).

**Why it was stopped** (`KILLED.md`; two independent auditors and both builders measured it):
- *Gradient difference:* everything except the module is linear, so subtracting the gradient on two halves of the free
  sample exposes the module. It solves 96% of OR/AND slots with no names, and the grader dry run gives S* 0.57 (kill line 0.35).
- *Remedies that leave another script:*
  - fixed gradient: a linearity test via the effect tool names the cues on 81/81 planted slots;
  - gradient-free: finding latents becomes group testing, and no budget-respecting script reaches the 60% reference bar
    (best 32% with names vs 15% without);
  - nuisance units: they stop plain gradient-difference (60/60 down to 4-9/60), but a no-name interaction script restores 60/60.
- *Sample-pattern leak:* the sample texts give the mechanism on 86/86 slots, and free logits separate planted from null at AUC 0.99.

**Verdict:**
- A skeptic re-tested the decision to stop and upheld it (KILLED.md section 9, which corrects two overstatements).
- No v3 model episodes ran, so there is no forensics report in the LUNA_EPISODES format.
- The planner recommends changing direction (v4: an open cue grammar, heads trained on data, a budget that makes
  enumeration infeasible, and a gated "tool-algebra red-team" baseline in Gate 0). It is estimated at more than one 10 h iteration.

**Reusable:**
- text encoding that rejects long texts instead of truncating them (v2's 96-token channel is closed);
- a factorial hidden grid with exact CPU grading (SE 0.011);
- continuous sub-scores;
- the open-menu pair grader and exact detectors;
- the harness fixes and the isolated launcher (now on main, section 5).

Branch task/shifthunt3 is local only.

## 3. Why small models fail (`docs/results/shifthunt/SMALLMODEL_FAILURES.md`)

- **Haiku 4.5 has no method.** It names cues from how they co-occur with labels in the sample (7/22). It claims a cue on every null probe (13/13).
  It almost never measures the probe on texts it writes (1/10 episodes with >= 5 matched pairs). Once it ran a correct pair that showed no effect
  and claimed the cue anyway. It stops early (21-35 of 150 tool calls). Even with perfect naming and null calls it would still fail 8/10.
- **gpt-6-luna has the method but under-fills.** It names well (19/22) and picks the right latents (88% overlap with the big models), but only about 4 of 20.
  It never checks removal against the bar. Fixing removal alone would give 6/10.
- **Diagnostics** (pre-registered, non-scored, same instances):

| luna arm | pass | named | null false claims | named slots clearing bar | median latents |
|---|---|---|---|---|---|
| baseline (medium) | 0/10 | 19/22 | 5/13 | 2/19 | 4 |
| effort high | 1/10 | 20/22 | 5/13 | 4/20 | 4.5 |
| medium + method hint | 1/10 | 17/22 | 4/13 | 14/17 | 20 |

  Effort is not the explanation. A method hint fixes removal but not naming or null calls: small models fix one stage and break another.
  No harness cap was hit. One TASK.md ambiguity to fix next time: removal is measured on held-out texts, not on the confounded sample.

## 4. Other studies

- **FeatureMatch: "mostly measuring style, not interpretability"** (`docs/results/featurematch/VERDICT.md`). The style-robust recipe
  (6 styled texts per option, pick the max) gets 0.873 of planted slots on the filtered pool. Even on the original pool, a script using the task's own
  `generate` tool gets 0.441 against a 0.15 gate. Only 7% of pooled latents (4% of topic latents) keep their concept across writing styles.
  Lessons: an anti-shortcut filter can select for artefacts (the name filter was involved in 84% of the exclusions of style-robust latents; it was the only reason in 35%);
  define answer keys on the distribution the agent will probe with; pre-register a scripted-recipe stop rule; small latent pools invite
  memorisation under RL.
- **LatentKnockout: NO-GO as designed** (`docs/results/latentknockout/FEASIBILITY_VERDICT.md`). Small knockout sets exist (30/43 pairs), but
  naive top-5 attribution reaches half the reference's score on 70% of feasible cells. A top-1-flip metric mostly counts near-ties
  (median clean lead 1.75 logits). Research question worth owning: famous concepts (Texas, English, popular sports) resist 5-latent
  knockout in a 16k SAE. A strict redesign is specified (about 4 GPU-hours of stop-early gates; about 10% chance to pass); it is held.
- **BoolIntermediates: too easy** (12/12 Opus). Agents rebuild the network from `weights` and solve it exactly offline. Fix: an activations-only tier (held).
- **LatentDiff: too easy** (6/6 Opus). A single per-token-spread statistic separates plants from decoys. Fix: matched decoy statistics (held).
- **Dropped:** EditFind (ROME edits are not specific, so the answer key is ill-posed), T2Ravel (the layer predicts null 100%), SilentPathway
  (frontier agents solve it in 10-13 turns). **ResidualRecall:** T1 passes; the T2 reference fails (rank-6 edit); held.

## 5. Infrastructure, incidents and caveats

- **Crash (Oct 2 03:10 UTC):** a 19.5 GB Python job ran the 30 GB machine out of memory. Fixes: 16 GB swap, user memory capped at 26 GB, per-job
  `systemd-run` caps, and memory rules in BUILDER_GUIDE. The interrupted fix stages were relaunched with their original prompts.
- **Harness hardening:** transcript discovery now audits only the transcript whose first message is the episode prompt. About 20 audit false-positive
  patterns were fixed, each with must-still-flag twin tests and replays of every recorded transcript. Validity rules were added: solver_failed,
  no_successful_call, infra_failure. Known gaps: some process/network calls made from Python are not flagged; new false positives keep appearing.
- **Test-agent isolation (Dan asked):** Claude test agents were Claude Code subagents of the orchestrator session. They are NOT OS-isolated: they
  run with the session's file access, see the repo cwd, recent commit subjects and shared scratch paths, and are held back only by prompt rules plus the
  post-hoc audit. No agent was caught reading outside its sandbox. OpenAI agents run sandbox-confined (scrubbed environment, command guard, no repo
  context).
  **Update Oct 4:** `common/claude_agent.py` (on main) runs a headless Claude agent fully isolated:
  - bubblewrap with a separate network namespace, an egress allowlist and an auth-injecting proxy (no credential inside the jail);
  - a fresh config dir;
  - scripted red-team: 115/115 attempts contained, and a live Haiku episode passed.
  It is not yet used for a ShiftHunt run; the direct context-exposure control (Opus confined) is now possible.
- **Answer material in local git history:** task/shifthunt (commit a90db0a7) and the featurematch fix-stage commits hold per-instance answers. Do not push
  those branches as they are. Results reach main only as these redacted copies.
- **Process note:** three verifier agents declined to write audit-evasion test inputs. Do not delegate that again. Adversarial coverage comes from
